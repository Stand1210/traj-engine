# M7.0 真实租户试点手册

> 状态：**试点流程已定义，等待真实业务结论回填。**
> 目标：用一个真实 Langfuse Project 验证「接入 → 聚类 → 告警 → 复核 → 校准」
> 的业务可用性，而不是继续扩大工程功能。

## 1. 试点原则

1. 一个 Langfuse Project 只对应一个业务本体，不混接多个 agent。
2. 首轮只做受控规模，不追求全量；目标是让业务方看懂结果。
3. 告警先控量，再谈召回；告警通道一旦失去可信度会直接被关闭。
4. 人工复核是业务验收核心，不能全部用合成标签替代。
5. 每个结论必须能回到 Run、trace score 和 evidence，不接受口头判断。

## 2. 准入条件

| 项 | 要求 |
|---|---|
| Langfuse | Cloud v4 或自托管 v4，一个独立 Project |
| 轨迹规模 | 首轮建议 100~1000 条，不少于 20 条 |
| 本体 | Tier 0/Tier 1 完成注册并通过预检 |
| 凭据 | 只保存在 `.env` 或环境变量，不得入库 |
| 人工复核人 | 至少 1 名业务专家，建议 2 名 |
| 观察周期 | 首轮后连续 3~7 天 R1 |

## 3. 试点流程

### 3.1 受控首跑

1. 与业务方确认 Langfuse Project 名称和轨迹时间窗。
2. 执行受控 Run，首跑建议 `limit=100~1000`。
3. 使用 `platform/scripts/pilot_report.py` 生成工程指标。
4. 与业务专家共同查看聚类分布与 Top 告警。
5. 对结论有分歧时记录原因，不现场调参。

开发环境可用现有真实 Project 演练：

```powershell
python platform/scripts/langfuse_production_smoke.py `
  --profile cloud-v4 `
  --project-name development_env `
  --window-start 2026-11-12T08:00:00Z `
  --window-end 2026-11-12T09:30:00Z `
  --limit 20 `
  --page-size 1000
```

### 3.2 生成验收报告

```powershell
python platform/scripts/pilot_report.py `
  --db platform/var/traj-engine.db `
  --output platform/var/pilot-report.md
```

脚本默认选择最近一次成功的 R1/R2。也可以指定 Run：

```powershell
python platform/scripts/pilot_report.py --run-id <run-id> --output platform/var/pilot-report.md
```

报告包含：

- Run、租户、本体与运行时长；
- 轨迹数、聚类数、弃权数、告警数；
- 簇大小分布；
- Top 告警与原因；
- 人工复核分布；
- 校准指标；
- 工程门禁与待完成项；
- 人工检查清单。

### 3.3 人工复核

1. 从告警工作台或复核队列选取样本。
2. 复核 `agree` 表示算法判断与业务判断一致。
3. 复核 `disagree` 必须填写原因，优先归类为：
   - 算法误报；
   - 算法漏报；
   - 业务上下文不足；
   - 本体范围错误；
   - 轨迹数据质量异常。
4. 达到 20 条复核后触发校准。
5. 校准激活后观察 Top 告警排序是否朝业务预期移动。

### 3.4 连续观察

| 天数 | 动作 | 关注点 |
|---|---|---|
| D1 | 生成报告 | 首轮结构是否可解释 |
| D2~D3 | 复核 20~50 条 | 告警可信度与原因分布 |
| D4~D7 | 观察 R1 | novelty、告警预算、失败率 |
| D7 | 汇总结论 | 是否允许扩大规模 |

## 4. 验收门禁

### 必须通过

1. Run 状态为 `succeeded`。
2. 有效轨迹不少于 20 条。
3. 正式告警数不超过当前预算。
4. 扣分与证据残差接近 0。

### 试点建议

1. 人工复核不少于 20 条。
2. 存在已激活校准版本。
3. Top 告警中业务可理解比例不低于 80%。
4. 每日人工处置时间不超过预期。

### 暂停或降级

1. 正式告警中业务确认误报占比过高。
2. 聚类结果被业务方判定为不可解释。
3. 弃权率持续上升且无法归因。
4. 运行失败或超时影响租户正常流量。
